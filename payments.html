01 · What is it

Payment integrations, explained in plain English

Stripe, PayPal and Chargify each run their own billing engine – invoices, dunning, upgrades, refunds and cancellations all happen there first. Left alone, that data stays trapped in the billing dashboard while sales and support work from HubSpot with no idea what’s actually happening to an account. Payment integration means every one of those events lands in HubSpot the moment it happens, as a deal, a property update, or a timeline event – so "is this customer paying, upgrading, or about to churn" is a question anyone on your team can answer without opening a second tab.

02 · Why it matters

What breaks without it

01

Blind renewal conversations

Sales calls a customer about upsell timing without knowing a payment just failed – an easily avoidable, easily embarrassing mistake.

Finance's numbers and HubSpot's deal values drift apart the moment someone upgrades, downgrades, or gets a refund outside a manual export.

Multi-gateway chaos

Businesses running Stripe and PayPal and Chargify need one consistent view in HubSpot, not three different half-synced pictures.

03 · Under the hood

A webhook handler, for context

StripeWebhookController.php
class StripeWebhookController
{
    public function handle(Request $req)
    {
        // verify the signature before touching anything
        $event = Webhook::constructEvent(
            $req->getContent(), $req->header('Stripe-Signature'), config('stripe.secret')
        );

        // idempotency: skip if we've already processed this event id
        if (ProcessedEvent::exists($event->id)) return response(200);

        match ($event->type) {
            'invoice.paid' => Hubspot::markDealPaid($event),
            'invoice.payment_failed' => Hubspot::flagDunning($event),
            'customer.subscription.updated' => Hubspot::syncPlanChange($event),
            default => null,
        };

        ProcessedEvent::record($event->id);
        return response(200);
    }
}
